## Q6 — Kerberoasting in Active Directory

**Question:** How does Kerberoasting work in Active Directory environments and which HTB machines demonstrate it?

**Answer:**

**Kerberoasting in Active Directory**

- **What it is** – An offline password‑cracking technique that targets service accounts in AD.  
  1. An attacker requests a Kerberos TGS‑REP for a service principal (e.g., `HTTP/hostname`).  
  2. The domain controller issues a ticket that contains the service account’s NTLM hash.  
  3. The attacker captures the ticket (the “Kerberoast” hash) and later cracks it with a password‑list or brute‑force tool.  
  4. Successful cracking yields the plaintext password of the service account, which can be used for lateral movement or privilege escalation.  
  (seen on: **htb-delegate**)

- **Why it works** – Service accounts often have complex passwords and are not subject to the same password‑policy restrictions as user accounts, making them attractive targets.  
- **Typical workflow** –  
  * Enumerate service principals (e.g., via `setspn -q *`).  
  * Request tickets for each principal.  
  * Extract the hash from the ticket.  
  * Crack offline with tools such as `hashcat` or `John the Ripper`.  
  (seen on: **htb-delegate**)

## Q10 — Docker container breakout

**Question:** How is Docker container breakout or escape achieved across HTB machines?

**Answer:**

**Docker container breakout / escape on HTB**

- **runc file‑descriptor leak (CVE‑2024‑21626)**  
  - Exploits a bug in `runc` ≤ 1.1.11 that leaks a file descriptor, allowing a container process spawned with `runc exec` to have its working directory mapped into the host namespace.  
  - The attacker can then read/write host files and escape the container.  
  - *Seen on:* `htb-runner` (Shell as root > CVE‑2024‑21626) (seen on: Runner)  

- **cgroup escape (CVE‑2022‑0492)**  
  - Uses a flaw in the cgroup v2 implementation that lets a privileged container modify the `cgroup.procs` file and inject a process into the host’s PID namespace.  
  - The exploit is often combined with OverlayFS tricks to gain root on the host.  
  - *Seen on:* `htb-carpediem` (Shell as root on Host > CVE‑2022‑0492) (seen on: Carpediem)  

- **Host share abuse / Docker‑host share escalation**  
  - When a container mounts a host directory (e.g., `/var/www/html` or `/tmp`) with write permissions, the attacker can place malicious binaries or scripts that run with the container’s user but are executed on the host.  
  - This technique is frequently used in conjunction with other privilege‑escalation vectors (e.g., CAP_DAC_READ_SEARCH) to read host files or spawn a root shell.  
  - *Seen on:* many HTB machines listed in the Graph Findings (e.g., `htb-cybermonday`, `htb-analytics`, etc.) (seen on: many machines)  

- **General approach**  
  1. **Recon** – Identify that the target is running Docker, the container runtime (`runc`), and whether privileged containers or host mounts are present.  
  2. **Foothold** – Exploit a known container‑escape CVE (runc or cgroup) or abuse a host mount to drop a payload.  
  3. **Lateral Movement** – Once a host process is spawned, use it to read sensitive files or launch further exploits.  
  4. **Privilege Escalation** – Escalate to root on the host (e.g., via CAP_DAC_READ_SEARCH, setuid binaries, or kernel exploits).  

These techniques are the primary ways HTB machines achieve Docker container breakout or escape.

## Q13 — SUID binaries and GTFOBins Linux privesc

**Question:** How are SUID binaries and GTFOBins abused for Linux privilege escalation across HTB machines?

**Answer:**

**SUID binaries & GTFOBins – Linux privilege‑escalation tactics on HTB**

- **SUID binaries**  
  * Attackers locate binaries that run with the file owner’s privileges (often root).  
  * Common abuse methods include:  
    - **Replacing the binary** with a malicious copy that executes a shell or payload.  
    - **Exploiting mis‑configured SUID binaries** that accept user input (e.g., `sudoedit`, `passwd`, `chsh`) to run arbitrary commands as root.  
  * These techniques were observed on a wide range of HTB machines, e.g.:  
    - `htb-backdoor`, `htb-analytics`, `htb-guardian` (seen on: MachineA, MachineB, MachineC).  

- **GTFOBins**  
  * GTFOBins is a curated list of binaries that can be abused to bypass security controls.  
  * Attackers use them to:
    - **Execute arbitrary commands** (e.g., `sudo`, `perl`, `python`, `awk`, `sed`) with elevated privileges.  
    - **Escalate privileges** by chaining commands that leverage SUID binaries or other mis‑configurations.  
  * GTFOBins abuse was reported on many HTB machines, including:  
    - `htb-backdoor`, `htb-analytics`, `htb-guardian` (seen on: MachineA, MachineB, MachineC).  

**Bottom line:**  
SUID binaries and GTFOBins are common vectors for Linux privilege escalation on HTB. Attackers typically locate a SUID binary, replace or exploit it, or chain it with a GTFOBin to run arbitrary code as root. These tactics were consistently seen across numerous machines such as `htb-backdoor`, `htb-analytics`, and `htb-guardian`.
