## Kerberoasting in Active Directory

### How Kerberoasting Works
Kerberoasting targets service accounts in Active Directory by requesting Ticket Granting Service (TGS) tickets for Service Principal Names (SPNs) and cracking them offline:

1. **Authentication**: Attacker authenticates to the domain (requires valid domain credentials)
2. **SPN Enumeration**: Identify user accounts with registered SPNs (service accounts)
3. **TGS Request**: Request a TGS ticket for the target SPN from the KDC
4. **Offline Cracking**: The ticket is encrypted with the service account's password hash (RC4_HMAC_MD5 or AES). Attacker extracts the hash and performs offline brute-force/dictionary attacks
5. **Credential Reuse**: Cracked password often reused across accounts or provides elevated access

**Key Requirement**: Valid domain account to authenticate to KDC and request TGS tickets (seen on: htb-active)

### HTB Machines Demonstrating Kerberoasting

| Machine | Context / Usage |
|---------|-----------------|
| **htb-active** | "opportunity to use Kerberoasting against a Windows Domain" (seen on: htb-active) |
| **htb-rebound** | "combine AS-REP-Roasting with Kerberoasting to get an crackable hash for a service account" (seen on: htb-rebound) |
| **htb-sauna** | "using a Kerberoast brute force on usernames to identify a handful of users" (seen on: htb-sauna) |
| **htb-administrator** | "abuse with a targeted Kerberoasting attack" after gaining GenericWrite over a user (seen on: htb-administrator) |
| **htb-tombwatcher** | "targeted Kerberoasting" as part of BloodHound path to another user (seen on: htb-tombwatcher) |

### Typical Tooling (from context)

- **Hashcat / John the Ripper** – offline cracking of extracted hashes (RC4_HMAC_MD5 mode 13100, AES256 mode 19600, AES128 mode 19700)

## Q12 — DCSync attack

**Question:** Which HTB machines demonstrate the DCSync attack and how does it work?

**Answer:**

# DCSync Attack Cheatsheet

## Overview
DCSync is an Active Directory attack where an attacker with specific permissions (such as "Replicating Directory Changes" or "Replicating Directory Changes All") replicates the Domain Controller's directory data as if they were another Domain Controller. This allows the attacker to dump the NTDS.dit database, extracting password hashes for all domain accounts, including the Domain Administrator. (seen on: htb-sizzle, htb-forest, htb-vintage, htb-sauna, htb-administrator, htb-flight, htb-hathor)

## Prerequisites
*   **Permissions:** The user must have "Replicating Directory Changes" and "Replicating Directory Changes All" permissions, typically held by Domain Admins or Domain Controllers. (seen on: htb-hathor)
*   **Network Access:** Ability to communicate with the Domain Controller on TCP 445, 135, and high RPC ports. (seen on: htb-sauna)

## Execution Techniques

### 1. Using `secretsdump.py` (Impacket)
This is a common method to perform DCSync from a remote host (e.g., Kali) without port forwarding, provided network access to the DC is available.

*   **Basic DCSync (Password Auth):**
    ```bash
    secretsdump.py 'username:password@dc_ip'
    ```
    *Example:* `secretsdump.py 'svc_loanmgr:Moneymakestheworldgoround!@10.10.10.175'` (seen on: htb-sauna)

*   **Basic DCSync (Kerberos Auth):**
    ```bash
    secretsdump.py -k -no-pass domain
    ```
    *Note:* May fail with `KRB_AP_ERR_SKEW` if clock skew is too great. (seen on: htb-flight)

*   **Targeted User Dump:**
    If full dump fails due to policy restrictions or errors, target a specific user (e.g., administrator):
    ```bash
    secretsdump.py -k -no-pass domain -just-dc-user administrator
    ```
    *Note:* This implies the `-just-dc` switch. (seen on: htb-flight)

*   **Just DC (No User Specified):**
    ```bash
    secretsdump.py -just-dc username:password@dc_ip
    ```
    *Example:* `secretsdump.py -just-dc mrlky:Football#7@10.10.10.103` (seen on: htb-sizzle)

### 2. Using `netexec` (NXC)
Can be used to dump NTDS hashes via SMB if the user has the necessary replication rights.

*   **Command:**
    ```bash
    KRB5CCNAME=dc01\$@cifs_dc01.vintage.htb@VINTAGE.HTB.ccache netexec smb dc01.vintage.htb -k --use-kcache --ntds --user administrator
    ```
    *Output:* Dumps NTDS hashes to a log file. (seen on: htb-vintage)

### 3. Using PowerShell (`Get-bADpasswords`)
Requires "Domain Admin" privileges or delegated Domain-level permissions for "Replicating Directory Changes" and "Replicating Directory Changes All". (seen on: htb-hathor)

## Troubleshooting
*   **Clock Skew Errors:** If `secretsdump.py` fails with `KRB_AP_ERR_SKEW(Clock skew too great)`, it indicates a time synchronization issue between the attacker and the DC. (seen on: htb-flight)
*   **Policy Restrictions:** If `Policy SPN target name validation might be restricting full DRSUAPI dump` appears, use the `-just-dc-user` flag to target specific accounts. (seen on: htb-flight)

## Observed Machines
*   **htb-sizzle:** Used `secretsdump.py -just-dc` to dump administrator hash. (seen on: htb-sizzle)
*   **htb-forest:** Used DCSync to dump administrator hashes after gaining initial access. (seen on: htb-forest)
*   **htb-vintage:** Used `netexec` with Kerberos ccache to dump NTDS. (seen on: htb-vintage)
*   **htb-sauna:** Used `secretsdump.py` with password authentication. (seen on: htb-sauna)
*   **htb-administrator:** Final step to dump domain administrator hash. (seen on: htb-administrator)
*   **htb-flight:** Demonstrated troubleshooting clock skew and policy restrictions with `secretsdump.py`. (seen on: htb-flight)
*   **htb-hathor:** Identified permissions required for DCSync via `Get-bADpasswords`. (seen on: htb-hathor)
