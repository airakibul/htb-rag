## Q6 — Kerberoasting in Active Directory

**Question:** How does Kerberoasting work in Active Directory environments and which HTB machines demonstrate it?

**Answer:**

**How Kerberoasting works in Active Directory**

- An attacker first obtains a **valid domain account** (any regular user credential).  
- Using that account, the attacker asks the **Key Distribution Center (KDC)** for a **Ticket‑Granting Service (TGS) ticket** for a service principal name (SPN) that belongs to a **service‑account** (e.g., `http/webserver.domain.com`).  
- The KDC returns the TGS **encrypted with the NT‑LM hash of the service‑account’s password**.  
- Because the attacker does **not need to present the ticket to the service**, they can **extract the encrypted portion** and perform an **offline brute‑force / dictionary attack** against the hash to recover the service‑account password.  
- Once the password is cracked, the attacker can **authenticate as that service account**, often gaining privileged access or the ability to move laterally within the domain.

*(All of the above steps are described in the “Kerberoasting > Background” section of the Active write‑up.)*  

**HTB machines that demonstrate Kerberoasting**

- **Active** – provides a basic Kerberoasting scenario on a Windows domain. (seen on: Active)  
- **Sauna** – uses Kerberoasting (and AS‑REP roasting) to obtain a user hash and later perform a DC‑Sync attack. (seen on: Sauna)  
- **Sizzle** – shows multiple ways to obtain a TGS ticket locally and run `GetUserSPNs.py` for Kerberoasting. (seen on: Sizzle)  
- **Tombwatcher** – BloodHound is used to locate a user for targeted Kerberoasting. (seen on: Tombwatcher)

  - (seen on: htb-pivotapi)

  - Once the attacker has a System‑level process, they can read protected files, dump credentials, or perform any action that requires the highest local privilege.

### How DCSync works (as illustrated by the machines above)

1. **Prerequisites**  
   * The attacker must have **SeBackupPrivilege** or **SeRestorePrivilege** on the domain controller (or a DC‑like account).  
   * A valid Kerberos TGT for a privileged account is required (obtained via Kerberoasting, delegation, or a pre‑existing credential).

2. **Execution**  
   * **Impacket’s `secretsdump.py`** or **`netexec`** is used to issue a **DRSUAPI** request to the DC.  
   * The request asks the DC to replicate its own NTDS database to the attacker, effectively performing a “copy” of the domain controller’s password data.  
   * The tool receives the NTDS.DIT data and extracts the **NTLM hashes** for the requested accounts (often the Administrator).

3. **Result**  
   * The attacker obtains the **NTLM hash** of the target account (e.g., Administrator).  
   * With the hash, the attacker can perform pass‑the‑hash, pass‑the‑ticket, or brute‑force attacks to gain higher privileges or a full domain‑level shell.

These steps are demonstrated across the listed HTB machines, each using slightly different tools or conditions but all achieving the same goal: extracting domain‑controller credentials via a DCSync attack.

## Q13 — SUID binaries and GTFOBins Linux privesc

**Question:** How are SUID binaries and GTFOBins abused for Linux privilege escalation across HTB machines?

**Answer:**

**SUID binaries**

- **What they do** – A file with the Set‑UID bit (`-rwsr-xr-x`) runs with the privileges of its owner (usually root).  
- **How they’re abused** – If the binary accepts user‑supplied arguments or can be tricked into executing arbitrary commands, an unprivileged user can run it as root.  
- **HTB examples**

**GTFOBins**

- **What they are** – A curated list of legitimate binaries that can be abused to gain higher privileges (e.g., by manipulating environment variables, arguments, or capabilities).  
- **Common GTFOBins techniques**  
  - **Perl** – `perl -e 'use POSIX qw(setuid); POSIX::setuid(0); exec "/bin/sh";'` attempts to drop privileges to root and spawn a shell. On *Nunchucks* this works for `whoami` but fails for a shell due to AppArmor restrictions. (seen on: Nunchucks)  
  - **LD_PRELOAD** – Load a malicious shared object that calls `setuid(0)` and `system("/bin/bash")`. On *Clicker* a `.so` is built locally, copied to `/tmp`, and executed with `LD_PRELOAD=/tmp/shell.so`. (seen on: Clicker)  
  - **Alternative GTFOBins** – The writeup notes that *htb‑schooled* contains other GTFOBins that can be leveraged. (seen on: htb‑schooled)  

**How they’re combined**

1. **Identify a SUID binary** (e.g., `/usr/bin/sudo`, `/bin/mount`, `/usr/bin/passwd`).  
2. **Find a GTFOBin that can manipulate that binary** (e.g., use `perl` to setuid to 0, or use `LD_PRELOAD` to inject code).  
3. **Execute the SUID binary with crafted arguments or environment** so that the GTFOBin logic runs with root privileges, giving the attacker a root shell or the ability to run arbitrary commands as root.  

These patterns recur across many HTB machines, with each machine offering a different SUID binary or GTFOBin that can be abused to elevate privileges.

## Q15 — Samba RCE

**Question:** How was a Samba vulnerability exploited for remote code execution across HTB machines?

**Answer:**

- **Vulnerability**: Samba’s print subsystem (CVE‑2026‑4480) passes the client‑controlled job‑description string to the configured print command via the `%J` placeholder without escaping shell metacharacters.  
- **Exploit technique**:  
  - An attacker sends a specially crafted print job whose description contains unescaped shell metacharacters (e.g., `;`, `&&`, `|`).  
  - Samba forwards this string directly to the shell that runs the print command, causing the shell to execute the injected commands.  
  - This results in remote code execution on the target machine.  
- **Practical use on HTB**:  
  - The exploit was demonstrated on **htb‑abducted** by sending a malicious job description that triggered arbitrary command execution.  
  - A similar approach was scripted in **htb‑lame** (Samba 3.0.20 < 3.0.25rc3) using a Metasploit‑style SMB exploit that automates the job‑submission and command injection.  

(Seen on: htb‑abducted, htb‑lame)
